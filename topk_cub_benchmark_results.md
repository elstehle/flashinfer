# FlashInfer top-k: CUB `DeviceBatchedTopK` integration benchmarks

Environment: NVIDIA B200 (SM100). CCCL `cluster-topk-poc` (NVIDIA/cccl PR #9224), FlashInfer `exp/cub-cluster-top-k`. dtype fp32, int32 segment lengths. Timing via CUDA events (CUPTI not installed). The `CUB` / `CUB(sel)` column is `cub::DeviceBatchedTopK::MaxPairs` run in the same mode as FlashInfer. Generated 2026-07-07.

The variable-length path passes the actual per-call max segment length to CUB as a runtime bound, so `DeviceBatchedTopK` sizes its cluster launch to the real max instead of the static 1M ceiling. Without this, the deferred-segment path fell back to the wide multi-CTA cluster configuration for every segment and was 3x-12x slower in the high-row-count varlen cases.

Speedup columns: `CUBvsFI` > 1 means CUB is faster than FlashInfer's native path in the same mode. Per-column semantics and `n/a` conditions are documented in the NOTE lines inside each table.
