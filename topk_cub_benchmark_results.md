# FlashInfer top-k: CUB `DeviceBatchedTopK` integration benchmarks

Environment: NVIDIA B200 (SM100), CUDA 13.3, PyTorch 2.13, Python 3.14. CCCL `cluster-topk-poc` (NVIDIA/cccl PR #9224), FlashInfer upstream/main @0263dc29 (includes #4295). dtype fp32, int32 segment lengths. Timing via CUDA events without CUDA graphs (per #4295's use_cuda_graph=False; CUPTI not installed). The `CUB` / `CUB(sel)` column is `cub::DeviceBatchedTopK::MaxPairs` run in the matching FlashInfer mode. Generated 2026-08-06.

Post-#4295 FlashInfer decouples tie-break from deterministic: tie_break (SMALL/LARGE) drives deterministic set *selection*, while deterministic=True drives output *ordering*. The CUB path provides deterministic-set selection with unsorted output (tie_break under gpu_to_gpu) and does not reproduce FlashInfer's deterministic=True output ordering. FlashInfer's tie-break output is now unsorted too, so the tie-break comparison is apples-to-apples.

The variable-length path passes the actual per-call max segment length to CUB as a runtime bound, so `DeviceBatchedTopK` sizes its cluster launch to the real max instead of the static 1M ceiling. Without this, the deferred-segment path fell back to the wide multi-CTA cluster configuration for every segment and was 3x-12x slower in the high-row-count varlen cases.

Speedup columns: `CUBvsFI` > 1 means CUB is faster than FlashInfer's native path in the same mode. Per-column semantics and `n/a` conditions are documented in the NOTE lines inside each table.
